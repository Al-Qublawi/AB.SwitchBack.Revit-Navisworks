Hold Ctrl and click an element in Navisworks. The Revit session it belongs to selects that element, opens a 3D view, wraps a section box around it, zooms to it and comes to the front. It is made for coordination reviews: find a clash in Navisworks, fix it in Revit, without searching for the element.

SwitchBack has two halves and needs both: the Revit add-in and the Navisworks plugin. The Marketplace package installs both. Revit and Navisworks talk to each other on the same computer only; nothing leaves it.

Getting started

  1. Open the Revit project the Navisworks model was exported from.
  2. Open the model in Navisworks. Both sides start listening automatically.
  3. When more than one Revit is running: in Navisworks, AB Adv Tools tab > SwitchBack > Revit Target, and choose the Revit that should receive the elements. With one Revit running it pairs by itself.
  4. Hold Ctrl and left-click an element in Navisworks.

Revit selects the element in the active project, applies a section box with a 1 m margin, zooms to it and comes forward.

Why Ctrl+Click and not Ctrl+Shift+Click

Navisworks reserves Ctrl+Shift+Click: it expands the pick to the whole model file, so no single element can be found. Shift is therefore never part of the gesture, and a click with Shift held does nothing.

Settings

Everything is set from Settings on the Navisworks ribbon. Changes apply immediately; nothing needs restarting.

SettingDefaultWhat it does
Enable the triggerOnOff stops Navisworks sending anything to Revit.
Keys held while clickingCtrlCtrl, Alt or Ctrl+Alt. With neither ticked, every element you select is sent - useful for a dedicated review session, noisy otherwise.
Create a section boxOnOff: Revit only selects and zooms.
Section box margin1000 mmSpace left around the element inside the section box.
Create a 3D view if none is usableOnOff: Revit never creates a view.

The settings are kept in %LOCALAPPDATA%\ABSwitchBack\config.txt, shared by Revit and Navisworks.

What it changes in your model

Two view-level changes, each in its own named transaction, so Ctrl+Z reverses them:

ChangeWhen
Section box on the 3D viewEvery switch back (unless switched off)
A new 3D viewOnly when the project has no usable 3D view (unless switched off)

Nothing else is touched: no geometry, parameters, families, types, worksets, levels or deletions. Switch both options off and SwitchBack is strictly read-only. In a workshared model, if another user owns the 3D view, the section box is skipped and the element is still selected and zoomed.

How the Revit element is found

SwitchBack reads the Revit element id that the Navisworks export stored on the clicked item, or on one of its parents: a property tab named Element ID, Revit Element ID or Revit ID, or a property with one of those names. Only the active Revit document is searched; linked models are ignored, because an id from a link would point at a different element in the host model.

Troubleshooting

What you seeWhat it usually is
"The click selected the whole model file"Navisworks' Selection Resolution is set to File. Set it to First Object or Geometry in Options > Interface > Selection.
Nothing happens on Ctrl+ClickThe trigger is off, or a different key is set - see Status and Log in Navisworks. Shift must not be held.
"No Revit instance found"Revit is not running, or SwitchBack did not load in Revit - look for the AB Adv Tools tab there.
"Element not found in the active project"The Navisworks model came from a different project, another project is active in Revit, or the element is in a linked model.
No element id foundThe model was exported without Revit ids. The message lists the property tabs the item does have.
SwitchBack loads twice, or Revit reports a duplicate add-inThe publisher's own installer (from GitHub) is also installed. Keep one: uninstall either it or the Marketplace version.

Logs: %LOCALAPPDATA%\ABSwitchBack\logs, one file per Revit or Navisworks session (Status and Log opens the folder).
